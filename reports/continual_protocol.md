# Continual development protocol, fixed before accuracy scoring

This work extends the independent pilot on a new branch. The original single-update driver and prior artifacts remain available. No author implementation or accuracy reproduction is claimed.

The official MedXpertQA-MM dev split contains five questions. The user explicitly authorized a fixed test **development** subset targeting 64 stream questions and 16 probe groups. This subset is retired from future final-test use. Selection uses only the existing label-free views: connected components of shared resolved image references, one random representative per component, seed 42, fixed random order. The prior MM-7 engineering example and its image group are excluded. Patient-level independence and duplicate-image detection across different filenames are not established. No domain-boundary signal, theme ordering, or reset is used.

A private candidate manifest contains an ordered maximum prefix of 128 stream groups and 16 probe groups. Its SHA-256 is fixed before any new accuracy scoring. Engineering tests use the prior smoke input and two source-order dev examples. The final main manifest is sealed from the candidate prefix using complete measured engineering throughput. The target is 64; downgrade to 32 or 16 if necessary. Estimated work must fit within 70% of remaining time before the GPU stop. N=16 is engineering-scale evidence. There is one seed and no hyperparameter search. No optional method or longer stream is planned until the four-way target comparison has completed; such an extension is not necessary for this delivery.

Four configurations share the same underlying settings: Frozen greedy, Frozen Self-Consistency-8, Continual TTRL, and Continual SPINE. Both RL methods begin independently from the pinned original model. Each case receives greedy-before, eight fresh sampled responses, at most one update, and greedy-after. Actor parameters, CPU FP32 masters, AdamW moments and step counters persist. The fixed reference is a separate nontrainable original model evaluated on every actual generated prefix. TTRL uses all response tokens and no entropy band; SPINE retains the pilot selection/band/objective. This is an implementation-matched baseline, not verified author TTRL code.

Sampling remains temperature 0.7, top-p 0.95, top-k 0, eight responses and a 2048-token cap. Loss log-probabilities remain raw, untempered model probabilities. There is no importance correction for the sampling transformations; strict on-policy equivalence is not claimed. CPU generation/teacher-forcing consistency is checked at temperature 1/top-p 1/top-k 0 with 1e-6 absolute tolerance. A separate actual-model check allows 0.1 log-probability absolute difference for BF16 cached-vs-full-prefix kernels. It uses four tokens solely as an engineering diagnostic and preserves RNG; production output limits remain 2048.

Learning rate 1e-6, AdamW betas (0.9, 0.999), epsilon 1e-8, no weight decay, gradient-norm cap 1, PPO clip 0.2, KL coefficient 0.01, and lower/upper band coefficients 0.01 are retained from the pilot. Deterministic PyTorch algorithms and the CUDA deterministic workspace setting are newly explicit for restart testing. The pilot's nonempty-mask KL normalization without an extra denominator epsilon is retained. First-step KL=0 and raw ratio=1 do not validate long-term anchor or clipping effectiveness.

All-invalid groups skip the update and retain their prediction records. Equal rewards are identified as zero-advantage groups; the original band/KL terms and Adam momentum remain active. Such steps are not called evidence of effective RL learning. Invalid parsed predictions count as incorrect in accuracy denominators. Voting ties retain the pilot lexicographic rule.

Probe decoding is uniformly greedy, including the underlying frozen policy for the SC-8 baseline, at cursors 0, N/2 and N. Model modes and Python/NumPy/CPU/CUDA RNG states are restored after probing. Updated-policy drift is measured on the first current rollout at cursors 1, N/2 and N: exact full-vocabulary KL to the fixed base and separately named sampled-token log-ratios to behavior. Probe scores and all other correctness scores are produced only by a separate evaluator after prediction artifacts are written; they never control training.

Acceptance requires the existing core tests, degenerate-reward and input-isolation tests, and strict small-model 10-step versus fresh-process 5+5-step state/output equality. Actual-model acceptance compares two continuous cases with fresh-process 1+1 cases: every FP32 master, Adam tensor and actor buffer must agree within atol=1e-7/rtol=1e-6; RNG, counters and discrete generated outputs must agree exactly. Separate short checks cover both frozen baselines and continual TTRL. Reference parameters are compared in full against an initialization copy, and optimizer membership is checked. The long stream cannot start without a saved successful acceptance result.

Checkpoints reconstruct BF16 actor parameters from complete FP32 masters and include buffers, Adam state, RNG, processed IDs, cursor, update count, configuration, code commit, base revision and manifest checksum. Writes use a temporary directory and atomic rename; only the latest two complete checkpoints of each new run are retained. Interrupted predictions after a checkpoint are preserved separately before replay. No accuracy-selected checkpoint is created.

Main work advances the four methods in equal 16-case chunks where resources permit. A partial comparison uses only the fixed prefix completed by all four methods and reports other coverage separately. Full-state reload/save and model initialization costs are included. Frozen SC-8 and RL are not compute-matched. No bootstrap significance claims or smoothed small-sample trends are planned.
