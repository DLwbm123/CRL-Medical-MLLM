## 首轮问题与修复

首轮 `p1-20261004T134316Z` 在 103.11 秒内完成了机械更新流程，但严格答案抽取器只接受了 1/8 条输出，不能作为共识奖励链路通过的证据。该轮 checkpoint、原始结果和错误判定均保留，未覆盖成成功记录。

修复只处理明确的答案标记及其后的选项字母，允许附带选项说明，并避免空答案标记跨行吞掉后续标记；不会根据临床描述、图号或真实标签推断选项。缓存回放恢复了 7 条明确答案，票数分布为 4、2、1；仍有 1 条无效输出，奖励为零。中间的跨行解析问题在 CPU 缓存回放中被发现并修复，没有额外启动 GPU 作业。

重跑仍使用相同的原始底座、六图输入、种子 42、采样和更新配置。八条回答长度与首轮一致。两轮完整作业累计约 204.61 秒（约 0.0568 个 GPU 作业小时），这不是 GPU 满负荷计时，也不包括下载、环境安装和 CPU 检查。没有为达到某个准确率调整样本或超参数。

## 实现与验证边界

实现依据 [SPINE v2](https://arxiv.org/html/2511.17938v2)。所检查的官方仓库提交 `108247fabe62b0ad548f7e040fb9dc6aa9dc18fc` 仅含 README 和两张示意图，因此本仓库是独立代码。采用原生 PyTorch/Transformers，未使用作者的 EasyR1 训练实现；学习率、优化器、系数、prompt、答案抽取和数据选取等独立选择已写入配置。

数值检查通过：分块计算的全词表 entropy、KL 及梯度与 PyTorch 分布实现一致；Otsu 退化路径和 detached 熵带符合本实现定义；mask 外直接 logits 梯度为零；拆分 micro-batch 后使用全局分母保持 loss 一致；标签字段被拒绝，图像顺序保留，投票和已见答案格式有回归检查。mask 限制的是各位置的直接损失项，共享参数更新仍可能改变其他位置的预测。

本次恰好在第一次更新前计算 loss，actor 与固定 reference 相同，因此测得 KL 为零；这不是 KL anchor 长期有效的证据。KL 非零数值与梯度只在合成单元检查中验证。当前 driver 只允许一步，完整 checkpoint 不含优化器状态，不能直接当作可续训多步训练器。KL 分母没有添加论文中的 epsilon，而由非空选择约束保证可除，README 已说明此数值差异。

环境为 CUDA 12.8 / torch 2.7.1+cu128 / transformers 4.51.3，BF16 全参数计算配合 CPU FP32 master weights 和 AdamW 状态。环境依赖检查、CUDA BF16 运算及完整模型更新均通过。GPU 测试只覆盖 SPINE 分支；SLAKE 与 No adaptation/TTRL 的正式实验均未运行，作者完整评测器尚不可核验。
